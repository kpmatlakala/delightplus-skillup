# Model Answers – US 14933: Demonstrate an understanding of creating multimedia/web-based computer applications with scripting

**Unit Standard ID:** 14933  
**NQF Level:** 4  
**Credits:** 6  
**Qualification:** FETC: Information Technology: Systems Development (SAQA ID 78965)

---

## Activity 1 (10 marks) – Plan the use of a multimedia/web-based authoring computer application with scripting

**Key planning steps (based on the learning outcomes):**

1. **Identify user specifications** – Determine the topic, purpose, target audience, and objectives of the application. This forms the foundation of the development plan.  
2. **Justify tool selection** – Choose authoring tools (e.g., Adobe Animate, HTML5/CSS3/JS editors, WordPress, etc.) based on project requirements, budget, and team skills.  
3. **Identify hardware and software requirements** – List necessary equipment (computer, server, graphics tablet) and software (image editor, video editor, code editor).  
4. **Create a project plan** – Outline tasks, timelines, milestones, and budget. Monitor progress against the plan.  
5. **Configure the development environment** – Set up the computer, operating system, and associated systems (e.g., local web server, version control) as required by the plan.

**Detailed discussion points (for group activity):**

- **Audience analysis** – Age, technical level, cultural context, accessibility needs.  
- **Content structure** – Storyboard, navigation flow, interactive elements.  
- **Scripting requirements** – Decide which parts need client‑side scripting (JavaScript) or server‑side scripting (PHP, Python, etc.).  
- **Testing strategy** – Plan for unit testing, integration testing, and user acceptance testing.  
- **Legal compliance** – Copyright, privacy (POPIA), accessibility standards.

## Activity 2 (10 marks) – Design a multimedia/web-based computer application

**Key design activities (based on learning outcomes):**

1. **Generate design from user specifications** – Create a design document that aligns with the agreed topic, purpose, target audience, and objectives.  
2. **Create storyboard and flow diagram** – A storyboard visually shows each screen (frame) with rough sketches of content and layout. A flow diagram shows navigation paths between screens (e.g., main menu → sub‑page → back).  
3. **Apply effective communication principles** – Use consistent colour schemes, readable typography, intuitive navigation, and clear calls to action. Ensure the design follows web usability and accessibility guidelines (WCAG).

**Discussion points for group activity:**

- **Storyboarding tools** – Paper, digital tools (Figma, Balsamiq, Canva).  
- **Flow diagram conventions** – Rectangles for pages, diamonds for decisions, arrows for movement.  
- **User experience (UX) principles** – Keep it simple, minimise clicks, provide feedback for user actions.  
- **Responsive design** – Design for desktop, tablet, and mobile.  
- **Multimedia integration** – Plan where to place images, audio, video, and animations.

## Activity 3 (15 marks) – Identify different multimedia elements

Multimedia elements are various forms of content that combine text, graphics, audio, video, and animation to deliver an interactive experience.

**List of different multimedia elements (with explanations):**

| Element | Description | Examples / File formats |
|---------|-------------|--------------------------|
| **Text** | Written words, titles, body copy, captions. Must be readable and appropriate for the audience. | Plain text, HTML, PDF, TXT |
| **Graphics (images)** | Photographs, illustrations, icons, diagrams. Used to attract attention and explain concepts. | JPEG, PNG, GIF, SVG, WebP |
| **Animation** | Moving graphics or text. Can be simple (GIF) or complex (vector animation). Adds visual interest. | GIF, SWF (legacy), CSS animations, Lottie, WebM |
| **Audio** | Sound effects, background music, voice‑over. Enhances mood and provides alternative information delivery. | MP3, WAV, OGG, AAC |
| **Video** | Moving images with or without sound. Very effective for demonstrations, tutorials, storytelling. | MP4, WebM, AVI, MOV |
| **Interactive elements** | Buttons, forms, clickable hotspots, drag‑and‑drop activities. Require scripting (JavaScript). | Buttons, checkboxes, sliders, quizzes |
| **3D models / virtual reality** | Three‑dimensional objects or immersive environments (VR). Increasingly used on the web with WebGL. | glTF, OBJ, USDZ |
| **Data visualisation** | Charts, graphs, infographics that update dynamically. Often created with libraries like D3.js. | SVG charts, Canvas, Chart.js |

**Copyright and privacy note:** All multimedia elements must be either original, licensed, or used under fair use / open licences (Creative Commons). Respect POPIA when collecting or displaying personal data.

## Activity 4 (10 marks) – Create multimedia/web-based computer application scripts

**Steps to create scripts (for group discussion):**

1. **Demonstrate logic diagram (e.g., flowchart or pseudocode)** – Before coding, draw a logic diagram that shows the sequence of operations, decisions, and loops. This clarifies the script’s behaviour.  
2. **Configure the operating environment** – Set up the computer, development tools, and any required server or browser settings as per the plan.  
3. **Write script using standard features** – Use standard language constructs (variables, conditionals, loops, functions, events) of the chosen scripting language (e.g., JavaScript for client‑side). Follow coding conventions and comment the code.  
4. **Test and debug** – Run the script under most likely conditions (valid input, invalid input, edge cases). Use browser developer tools or console logs to identify errors. Correct syntax and logic errors. Repeat testing until the script behaves correctly.

**Group discussion topics:**

- **Choosing the right script type** – Client‑side (faster, no server load) vs server‑side (secure, database access).  
- **Common scripting tasks** – Form validation, dynamic content loading (AJAX), image sliders, interactive menus, animations.  
- **Testing techniques** – Unit testing, integration testing, user testing.  
- **Error handling** – Try‑catch blocks, user‑friendly error messages, logging.

**Example (JavaScript snippet for form validation):**
```javascript
function validateForm() {
    let name = document.getElementById("name").value;
    if (name === "") {
        alert("Name must be filled out");
        return false;
    }
    return true;
}
```

Activity 5 (5 marks) – Discuss the future of web-based multimedia (pairs)
Possible future trends (discussion points):

Increased use of WebAssembly (Wasm) – High‑performance code (C++, Rust) runs in the browser, enabling advanced multimedia applications (video editing, 3D games).

AI‑generated and personalised content – AI creates custom graphics, animations, and even video based on user preferences or behaviour.

Immersive experiences (WebXR) – Virtual Reality (VR) and Augmented Reality (AR) directly in the browser without plugins.

Real‑time collaboration – Multiple users interacting with the same multimedia content simultaneously (shared whiteboards, collaborative video editing).

Faster networks and wider bandwidth – Enables streaming of high‑resolution video, 8K, and lossless audio without buffering.

Web components and modular design – Reusable multimedia components (custom video players, 3D viewers) that work across frameworks.

Accessibility improvements – AI‑powered captions, audio descriptions, voice control for all multimedia content.

Sustainability and lightweight design – Optimised media formats (AVIF, WebP2) and green hosting reduce energy consumption.

Conclusion: The future of web‑based multimedia is richer, more interactive, and more accessible, driven by new standards, faster hardware, and AI.
