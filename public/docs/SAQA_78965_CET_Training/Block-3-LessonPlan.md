# **LESSON PLAN — 14908: Testing IT Systems Against Specifications**

**Module:** ITSD-14908 | Block 3 | Day 11  
**Training Intervention:** CET Lecturers Systems Development Training

## **Lesson Title**

**Testing IT Systems: Procedures, Diagnostics and Specification Compliance**

## **Lesson Overview**

This session introduces structured testing practices for hardware and software systems. Emphasis is placed on selecting appropriate test procedures, documenting test plans, collecting diagnostic data, and ensuring alignment with system specifications in CET environments.

## **Lesson Objectives**

By the end of this session, learners will be able to:

1.  Select appropriate hardware and software test procedures.  
    
2.  Apply and document structured test approaches.  
    
3.  Collect and record diagnostic information from system tests.  
    
4.  Prepare comprehensive testing plans aligned to system specifications.  
    

## **Lesson Content**

### **Session 1: Selecting Test Procedures**

-   Hardware test stages: Prototype testing, Development Acceptance Testing (DAT), Factory Acceptance Testing (FAT), Site Testing, Burn-in Testing, Final Acceptance  
    
-   Factors influencing testing effort: documentation quality, system size, lifecycle stage, team capacity, timelines  
    
-   Software testing considerations: User Acceptance Testing (UAT), safety-critical system requirements  
    

### **Session 2: Applying Test Procedures**

-   Developing a Test Approach Description (methodology, stakeholder contacts, issue tracking)  
    
-   Executing tests: defining conditions, cycles, access control checks  
    
-   Documentation: end-to-end test plans, interface registers, critical process mapping  
    

### **Session 3: Collecting and Recording Diagnostic Data**

-   Configuring systems for diagnostic data collection  
    
-   Manual vs automated test execution  
    
-   Capturing logs, system events, UI traces, and runtime diagnostics  
    

### **Session 4: Preparing Tests Against Specifications**

-   Planning for System Integration Testing  
    
-   Testing hierarchy: simple to complex; utility to end-user scenarios  
    
-   Environmental considerations (operating conditions, infrastructure constraints)  
    
-   Documenting scenarios, test cases, expected results, and traceability to specifications  
    

## **Facilitator Activities**

-   Icebreaker: Share a bug discovered and how it was reported.  
    
-   Mini-lecture: Overview of test procedure types and structured test approaches.  
    
-   Group activity: Draft a test plan for a student project submission system.  
    
-   Paired exercise: Identify factors affecting test effort.  
    
-   Distribute Testing Quick-Start Toolkit (test plan template, bug log, diagnostic checklist).  
    
-   Peer review of drafted test plans focusing on coverage and clarity.  
    
-   Participatory engagement through discussion and collaborative planning.  
    

## **Learner Activities**

-   Activity 1: Describe six hardware test programs.  
    
-   Activity 2: Identify and explain factors affecting test effort.  
    
-   Activity 3: Explain components of a structured Test Approach Description.  
    
-   Activity 4: Describe procedures for configuring and collecting diagnostic information.  
    
-   Activity 5: Explain preparation steps for System Integration Testing.  
    
-   Group Task: Develop a Test Plan and Diagnostic Checklist for a capstone prototype.  
    

## **Resources Required**

-   Printed test plan templates and diagnostic checklists  
    
-   Sample test scenarios and log examples (offline USB pack)  
    
-   Whiteboard and flip charts  
    
-   Bilingual glossary (Sepedi/Tshivenda key terms)  
    
-   Backup printed materials (offline contingency)  
    
-   Facilitator and Learner Guides (SAQA 14908)  
    
-   Laptop and data projector  
    

## **Assessment (Formative)**

-   Observation checklist (appropriate selection of test procedures)  
    
-   Submitted test plan and diagnostic checklist  
    
-   Peer feedback on clarity and specification alignment  
    
-   Exit reflection ticket  
    
-   Evidence aligned to SAQA 14908 summative requirements  
    

**Duration:** 300 minutes (5 hours)  
**Status:** Active

# **LESSON PLAN — 14919: Resolve Computer User Problems**

**Module:** ITSD-14919 | Block 3 | Day 12  
**Training Intervention:** CET Lecturers Systems Development Training

## **Lesson Title**

**User Support and Troubleshooting: Resolving Computer Problems Effectively**

## **Lesson Overview**

This session equips learners with structured troubleshooting and user support skills. Focus is placed on systematic problem intake, investigation, resolution, documentation, and escalation within CET support environments.

## **Lesson Objectives**

By the end of this session, learners will be able to:

1.  Receive and document user problems using defined parameters.  
    
2.  Investigate and classify problems (hardware, software, user-generated).  
    
3.  Implement and review solutions in consultation with stakeholders.  
    
4.  Close resolved cases with complete documentation.  
    
5.  Escalate unresolved problems according to support agreements.  
    

## **Lesson Content**

### **Session 1: Receiving User Problems**

-   Defining problem parameters and solution constraints  
    
-   Gathering accurate and complete information  
    
-   Planning a structured course of action  
    
-   Common issues: insufficient memory, adware, performance slowdown  
    

### **Session 2: Investigating Problems**

-   Reviewing logs and historical records  
    
-   Categorising issues: hardware, software, user error  
    
-   Recording symptoms for technical escalation  
    

### **Session 3: Implementing Solutions**

-   Evaluating solutions against original objectives  
    
-   Consulting stakeholders to confirm impact  
    
-   Standardising solutions for recurring issues  
    

### **Session 4: Closing Resolved Problems**

-   Reporting back to users  
    
-   Recording resolution details (problem, symptoms, actions taken, outcomes, timeline)  
    
-   Following organisational documentation standards  
    

### **Session 5: Escalating Unresolved Problems**

-   Understanding support agreements and service levels  
    
-   Escalation processes and communication  
    
-   Providing temporary workarounds where necessary  
    

## **Facilitator Activities**

-   Icebreaker: Share a challenging support experience.  
    
-   Mini-lecture: Problem parameters and structured troubleshooting.  
    
-   Role-play: Receiving and documenting a user problem.  
    
-   Group activity: Categorising hardware vs software vs user-created issues.  
    
-   Paired exercise: Draft a support ticket record.  
    
-   Distribution of User Support Quick-Start Toolkit (ticket template, escalation flowchart).  
    
-   Peer review of drafted support records.  
    

## **Learner Activities**

-   Define problem parameters and next steps.  
    
-   Describe common computer problems.  
    
-   Explain investigation and troubleshooting processes.  
    
-   Draft a support ticket record.  
    
-   Discuss standardisation and escalation procedures.  
    
-   Group Task: Role-play the full support lifecycle (Receive → Investigate → Implement → Close).  
    

## **Resources Required**

-   Support ticket templates and escalation flowcharts  
    
-   Sample scenarios and solution logs  
    
-   Whiteboard and flip charts  
    
-   Bilingual glossary  
    
-   Offline contingency materials  
    
-   Facilitator and Learner Guides (SAQA 14919)  
    
-   Laptop and data projector  
    

## **Assessment (Formative)**

-   Observation checklist (structured troubleshooting and stakeholder consultation)  
    
-   Submitted support documentation  
    
-   Peer review feedback  
    
-   Exit reflection ticket  
    
-   Evidence aligned to SAQA 14919 summative requirements  
    

**Duration:** 300 minutes (5 hours)  
**Status:** Active

# **LESSON PLAN — 120379: Work as a Project Team Member**

**Module:** ITSD-120379 | Block 3 | Day 13  
**Training Intervention:** CET Lecturers Systems Development Training

## **Lesson Title**

**Project Team Collaboration: Roles, Respect and Conflict Resolution**

## **Lesson Overview**

This session strengthens learners’ ability to function effectively within project teams. Emphasis is placed on collaboration, stakeholder engagement, diversity awareness, and constructive conflict resolution in CET project environments.

## **Lesson Objectives**

By the end of this session, learners will be able to:

1.  Explain criteria for effective participation in project teams.  
    
2.  Collaborate to enhance team performance.  
    
3.  Build positive relationships with stakeholders.  
    
4.  Apply strategies to manage diversity and resolve conflict.  
    

## **Lesson Content**

### **Session 1: Criteria for Effective Team Membership**

-   Team roles: Leader, Contributor, Facilitator, Recorder, Timekeeper  
    
-   Performance indicators: reliability, accountability, adaptability, communication  
    
-   Project scale considerations in CET contexts  
    

### **Session 2: Improving Team Performance**

-   Benefits of teamwork: shared knowledge, workload distribution, innovation  
    
-   Constructive behaviours: active listening, clarity, timely delivery  
    
-   Disruptive behaviours and their impact  
    

### **Session 3: Building Team and Stakeholder Relations**

-   Stakeholder identification (lecturers, students, administrators, IT support, community partners)  
    
-   Communication planning and feedback loops  
    
-   Cultural awareness and respect for diversity  
    

### **Session 4: Conflict Management**

-   Sources of conflict (role ambiguity, limited resources, communication gaps)  
    
-   Resolution techniques: mediation, compromise, structured escalation  
    
-   Role-play practice of common project conflicts  
    

## **Facilitator Activities**

-   Icebreaker: Positive and challenging team experiences.  
    
-   Mini-lecture: Team roles and performance criteria.  
    
-   Stakeholder mapping exercise.  
    
-   Behaviour identification activity (constructive vs disruptive).  
    
-   Conflict resolution role-play session.  
    
-   Distribution of Team Collaboration Quick-Start Toolkit (role cards, conflict flowchart).  
    
-   Peer review of team charters and communication plans.  
    

## **Learner Activities**

-   Identify team members and assigned roles.  
    
-   Explain the importance of teamwork in CET project delivery.  
    
-   Provide examples of effective teamwork practices.  
    
-   Identify disruptive behaviours and impacts.  
    
-   Discuss diversity and respect strategies.  
    
-   Participate in conflict resolution role-play.  
    
-   Group Task: Develop a Team Charter and Conflict Resolution Protocol.  
    

## **Resources Required**

-   Conflict resolution flowchart  
    
-   Stakeholder mapping templates  
    
-   Whiteboard and flip charts

-   Facilitator and Learner Guides (SAQA 120379)  
    
-   Laptop and data projector  
    

## **Assessment (Formative)**

-   Observation checklist (constructive participation and respect for diversity)  
    
-   Submitted Team Charter and Conflict Resolution Protocol  
    
-   Peer feedback
